# OpenCV 4.10.0 Reference Version & purecv ↔ OpenCV Comparison Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resolve [issue #165](https://github.com/webarkit/purecv/issues/165). Declare OpenCV **4.10.0** as the single parity reference, pin every OpenCV reference in the tree to it, keep it pinned with a test, and make the reference sources and the measurement tools reproducible. Then run the module-by-module **Comparison purecv ↔ OpenCV** asked for in the issue thread, assigning or splitting every existing open issue by module.

**Architecture:** Two parts.
- **Part A** closes #165 in one PR, made of separable commits.
  - One integration test, `tests/opencv_reference_links.rs`, rejects unpinned OpenCV links and bare `file.cpp:NN` citations. The ten references that drift today are fixed in the same task.
  - The reference sources become reproducible **without a submodule**. `bootstrap.py` is vendored from webarkit/WebARKitLib-rs into `cpp_ref/`, with safety patches. `cpp_ref/libraries.json` pins `opencv` and `opencv_contrib` by their 4.10.0 commits. `cpp_ref/requirements.txt` and `cpp_ref/package.json` pin the measurement tools (the Python wheel built from those same commits, and opencv.js 4.10.0).
  - `CONTRIBUTING.md` holds the policy once, and the agent instruction files point to it.
- **Part B** is the comparison. It has one umbrella issue and five sub-issues, in the order given in the thread: core → imgproc → features2d → video → calib3d. Each sub-issue produces one audit document, `docs/parity/<module>.md`, and files one issue per new divergence. **Audit PRs change no library code.** Fixes go through the issues they file.

**Tech Stack:**
- Rust 2021 (MSRV 1.88), with a `std`-only integration test and no new crate dependencies.
- Python ≥ 3.10, stdlib only, for `cpp_ref/bootstrap.py` and its `unittest` suite. CI covers 3.10 and 3.12.
- Measurements only:
  - Python ≥ 3.11 venv `cpp_ref/.venv` with `opencv-contrib-python==4.10.0.84`;
  - Node with `@techstark/opencv-js@4.10.0-release.1` under `cpp_ref/node_modules`.

**Spec:** [issue #165](https://github.com/webarkit/purecv/issues/165) (body + 2 comments), plus the maintainer's follow-ups in the planning session (2026-10-11): reproducibility through a vendored `bootstrap.py`, no submodule; no ADR for now.

**Base:** `origin/dev` = `c134aea` (v0.9.0 + #162). The local `dev` was 16 commits behind when planning started. Every line number below refers to `c134aea`.

**Interfaces (private to the test crate):**
- `const REFERENCE: &str = "4.10.0";`
- `const SCANNED: &[(&str, &str)] = &[("src", "rs"), ("examples", "rs"), ("benches", "rs"), ("crates/wasm/src", "rs"), ("docs/parity", "md")];` (directory relative to `CARGO_MANIFEST_DIR`, extension)
- `fn line_violations(line: &str) -> Vec<String>`: one message per offending reference.
- `fn content_violations(text: &str) -> Vec<(usize, String)>`: 1-based line plus message, via `str::lines()`.
- `fn scan(root: &Path, dirs: &[(&str, &str)]) -> (usize, Vec<String>)`: files scanned, plus sorted `"<relpath with />:<line>: <msg>"` entries. Recursive; skips roots that do not exist.

Rules in `line_violations`:
1. **Version segment.** After every occurrence of `docs.opencv.org/`, `github.com/opencv/opencv/blob/`, `github.com/opencv/opencv/tree/`, `github.com/opencv/opencv_contrib/blob/` or `github.com/opencv/opencv_contrib/tree/`, the **longest run of `[A-Za-z0-9._-]`** must equal `REFERENCE` exactly.
2. **Bare line citation.** Flag `.cpp:`, `.hpp:` or `.h:` immediately followed by an ASCII digit. **Exemption:** the match is the text of a markdown link. That means the next `](` on the line comes after only characters from `` 0-9 , - ` `` and is directly followed by `https://github.com/opencv/opencv/blob/` or `https://github.com/opencv/opencv_contrib/blob/`. Rule 1 still validates that URL.

`_checkout_state` → action. "Own toplevel" requires all of the following:
- `lib_dir` is a real directory, not a symlink or junction;
- `normcase(realpath(lib_dir)) == normcase(join(realpath(BASE_DIR), "src", name))`;
- a linked `cpp_ref/src` is refused before any write;
- `lib_dir/.git` is a real directory, not a gitfile or link;
- `os.path.samefile(<git rev-parse --show-toplevel>, lib_dir)`;
- `os.path.samefile(<git rev-parse --absolute-git-dir>, lib_dir/.git)`.

Never compare git-printed paths as strings: git prints long, `/`-separated, symlink-resolved paths, and Windows CI temp paths use 8.3 names. A link, junction or worktree pointing at another repository (e.g. `cpp_ref/opencv`) is therefore `corrupt`, never the script's own. `_rmtree` refuses links, and on POSIX it chmods with `st_mode | S_IWRITE`. "Clean" means `git status --porcelain=v1 -z --ignored --untracked-files=normal` prints nothing; split its output on NUL.

| State | Meaning | Action |
|---|---|---|
| `missing` | dir absent or empty | `git clone --branch <branch> <url> <dir>`, then `checkout --detach <commit>` |
| `ok` | own toplevel, HEAD == commit, clean | nothing |
| `drifted` | own toplevel, clean, HEAD ≠ commit | fetch if needed, then `checkout --detach <commit>` |
| `dirty` | own toplevel, not clean | **refuse** (non-zero), list the paths, suggest `--clean` |
| `corrupt` | dir non-empty, not its own toplevel | **refuse** (non-zero). With `--clean`: `_rmtree`, then clone |

- [ ] **Step 1: Write `docs/parity/README.md`** with:
  - **Reference:** links to `CONTRIBUTING.md#opencv-reference-version` and to this plan.
  - **What is compared.** The comparison works at two levels and never links C++ into purecv.
    1. **Source level → `inspected`.** The OpenCV 4.10.0 C++ in `cpp_ref/src/opencv` is read side by side with the purecv Rust. The reference is the **generic CPU path**.
       - The OpenCL, IPP, HAL and OpenVX back ends (`CV_OCL_RUN`, `CV_IPP_RUN*`, `CALL_HAL`, `CV_OVX_RUN`) are alternatives.
       - The `*.simd.hpp` / `CV_SIMD` code paths are optimisations of the generic path.
       - Where these back ends disagree with each other (as #161 found for FAST), note it on the row.
    2. **Behaviour level → `measured`.** The same inputs go through OpenCV 4.10.0 binaries and through purecv, and the outputs are compared. The binaries are:
       - the `cpp_ref/.venv` wheel, which is the C++ compiled from the very same commits and called from Python;
       - or opencv.js 4.10.0 (WASM, no IPP).

       The x86-64 wheels ship with Intel IPP and runtime SIMD dispatch **enabled**:
       - Measure with `cv2.ipp.setUseIPP(False)` by default, so that the measurement matches the generic path read at level 1.

  - **Statuses** (exactly these six):
    - `measured`: compared numerically with 4.10.0 through reproducible evidence; identical, or within a stated tolerance.
    - `inspected`: the 4.10.0 source was read side by side, or evidence exists that is not reproducible (issue comments, unidentified builds, other versions).

    - `intentional`: a deliberate difference, with the rationale.
    - `purecv-only`: an existing purecv item with no 4.10.0 counterpart.

  - **Direction** (for `diverges` only): `→ OpenCV` (purecv changes) or `keep?` (the maintainer decides; if kept, the row becomes `intentional`).
  - **Dimensions:**
