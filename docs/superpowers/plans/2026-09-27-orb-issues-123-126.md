# ORB fixes (#123, #124, #125, #126, #136) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the four open `Orb` issues:
- build the scale pyramid once (#123);
- blur before BRIEF like OpenCV (#124);
- score Harris only at keypoints (#125);
- reject parameters that are silently ignored (#126).

Also make `Orb` output identical on every platform (a prerequisite for pinning it with tests), and add the preventive FAST guard from #136.

**Architecture:** All production changes are in `src/features2d/orb.rs`:
- **Platform-independent maths:** level scales and orientation angles are computed in `f64` and rounded once to `f32`.
- **One pyramid:** the public `detect`, `compute` and `detect_and_compute` become thin wrappers. Each validates parameters, builds the pyramid once, and calls one of two private helpers that take the pyramid.
- **Local Harris:** Harris scoring switches from a full-level `corner_harris` map to a per-keypoint helper that is bit-identical to it.
- **Blur:** `compute` blurs each needed level with the existing `imgproc::gaussian_blur` before sampling BRIEF.

Tests go in `src/features2d/tests.rs`, plus a generated OpenCV reference fixture.

**Tech Stack:** Rust (crate `purecv`, features `std`, `parallel`, `simd`) and Criterion benches. The fixture generator runs on Node against a local OpenCV 4.10.0 `opencv.js` build at `D:/kalwalt-github/opencv-em/opencv_js/bin/opencv.js`. Cross-platform checks use WSL `Ubuntu-20.04`, which has Rust 1.93 and glibc 2.31.

**Spec:** GitHub issues webarkit/purecv #123, #124, #125, #126 and #136, plus #156 (platform determinism), filed with this plan (`gh issue view <n>`). The plan also relies on facts measured at `ef13ed8` (origin/dev) against the OpenCV 4.10.0 source and `opencv.js`. Where a task depends on one of those facts, it is quoted in the task.

## Decisions made in this plan (review these)

1. **Platform independence first (new Task 1).** At `ef13ed8`, `Orb::default().detect_and_compute` on the Task 1 image gives different results on Windows and Linux:
   - `pt` differs for all 163 keypoints at octaves 4–7, by up to 4 ULP. The cause is runtime `f32::powi`, whose precision Rust leaves unspecified.
   - `angle` differs for 55 of the 500 keypoints, by up to 3 ULP. The cause is `f32::atan2` from the platform's math library.

   With scales computed as an `f64` product rounded once to `f32` (which is OpenCV's `(float)pow((double)sf, n)`), and the angle, `cos` and `sin` computed in `f64` and rounded once, every field is bit-identical on Windows, Linux and wasm32. The wasm32 check was done by the issue's fact-checker, in both npm variants. On Windows the coordinates and descriptors are also unchanged; 166 of the 500 angles move, by at most 2 ULP. Without this change, the goldens that prove #123 and #125 change nothing would fail on Linux CI.
2. **#126 rejects bad values at use time, not in `Orb::new` or the setters.** Making those fallible would break the Rust API and `examples/match_features.rs:143`. The WASM constructor already returns `Result`, but it stays lenient, so Rust and JS fail at the same point. The checks follow OpenCV:
   - `patch_size < 2` is rejected by `detect`, `compute` and `detect_and_compute`. This is OpenCV's `CV_Assert(patchSize >= 2)` (orb.cpp:1018). Today `precompute_umax(0)` underflows at `orb.rs:481`, which panics in debug builds.
   - `first_level != 0` is rejected by all three.
   - `wta_k != 2` is rejected only when descriptors are requested (`compute`, `detect_and_compute`). OpenCV asserts `WTA_K ∈ {2,3,4}` only then (orb.cpp:1214).
   - `patch_size != 31` is rejected for descriptors, both in `Orb` and in the public `compute_orb_descriptor`, which today ignores the argument (`_patch_size`). OpenCV switches to a *random* 512-point pattern for patch sizes other than 31 (orb.cpp:1204-1222), and purecv only has `BIT_PATTERN_31`. `compute_orb_descriptor` also rejects `pattern.len() < 1024`; today that indexes out of bounds and panics.
3. **#125 keeps purecv's current Harris definition** (`corner_harris` with block 3, ksize 3, k 0.04), computed per keypoint and bit-identical to the full map. Switching to OpenCV's `HarrisResponses` would change which keypoints are kept, so it is left to #158.
4. **#124 uses the existing `imgproc::gaussian_blur(7×7, σ = 2, Reflect101)`.** Against OpenCV 4.10.0 on the reference fixture, the per-keypoint Hamming distance is mean 1.15 and max 3 with the blur, and mean 50.6 and max 74 without it. The remaining difference is #157: `gaussian_blur` truncates when converting to `u8`, and a rounding blur gives 0 bits. The test threshold is max ≤ 10 bits and mean ≤ 2.5 bits.
5. **Breaking changes are marked.**
   - #124 changes every descriptor.
   - #126 turns calls that used to return `Ok` into `InvalidInput`.
   - Both commits therefore use `fix(features2d)!:` with a `BREAKING CHANGE:` footer, so git-cliff flags them.
   - The platform fix (Task 1) moves some angles by up to 3 ULP only, so it is a plain `fix`.
6. **#136 needs no code change.** purecv's FAST scans a full score map and keeps no per-row candidate buffer. For `TYPE_9_16` it matches `opencv.js` exactly. The deliverable is a guard test; it was mutation-checked by injecting jsfeat's buffer, which made it fail.

## Review Focus

1. **Detection must not see the blur.** After #124, `detect_and_compute` keypoints must be bit-identical to before. This is pinned by the keypoint golden, which stays at `0x6d03920c` through Tasks 2–5.

```rust
struct Lcg(u64);
impl Lcg {
    fn next_u32(&mut self) -> u32 {
        self.0 = self.0.wrapping_mul(6364136223846793005).wrapping_add(1442695040888963407);
        (self.0 >> 33) as u32
    }
    fn below(&mut self, n: u32) -> u32 { self.next_u32() % n }
}
/// Mid-gray background, 500 filled rectangles (side 4..=63, value 0..=255), then ±6 noise.
fn lcg_textured(rows: usize, cols: usize, seed: u64) -> Matrix<u8> {
    let mut rng = Lcg(seed);
    let mut buf = vec![128i32; rows * cols];
    for _ in 0..500 {
        let w = 4 + rng.below(60) as usize;
        let h = 4 + rng.below(60) as usize;
        let x0 = rng.below(cols as u32) as usize;
        let y0 = rng.below(rows as u32) as usize;
        let v = rng.below(256) as i32;
        for y in y0..(y0 + h).min(rows) { for x in x0..(x0 + w).min(cols) { buf[y * cols + x] = v; } }
    }
    let mut img = Matrix::<u8>::new(rows, cols, 1);
    for (d, s) in img.data.iter_mut().zip(buf.iter()) {
        *d = (s + rng.below(13) as i32 - 6).clamp(0, 255) as u8;
    }
    img
}
```
