Headline findings, in order of impact (details in the rows, issues in
[Filed issues](#filed-issues)):

1. **Three panics in library code.** `gaussian_blur` with a non-square kernel and
   `sigma2 = 0` (index out of bounds: the X kernel is reused for Y), `hough_circles` with
   `dp = 0`, and, with `--features simd` only, `erode`/`dilate`/`morphology_ex` on any
   multi-channel image with a rectangular kernel (the SIMD padding is counted in pixels, not
   elements). OpenCV returns a result or a `cv::Exception` in all three cases.
2. **Float outputs rounded to integers.** `resize`, `pyr_down` and `pyr_up` round every
   output, also for `f32`/`f64` (`interpolated.round()`, `(sum / 256.0).round()`): a float
   pyramid or resize loses its fractional part (up to 0.5).
3. **Integer outputs truncate or wrap to 0** where OpenCV saturates (#157): `blur`,
   `box_filter` (unnormalised sums above 255 become 0), `gaussian_blur`, `bilateral_filter`,
   `sobel`/`scharr`/`laplacian` (u8 values above 255 become 0), the scalar `remap`/
   `warp_perspective` path and `threshold`'s `maxval`. Every site needs the shared
   `saturate_cast` of #189.
4. **The 8U fixed-point paths are not reproduced.** OpenCV's u8 `GaussianBlur` (bit-exact
   `ufixedpoint16`), `resize` (11-bit coefficients), `remap`/`warpPerspective` (coordinates
   quantised to 1/32 pixel, 15-bit weights) and `cvtColor` to gray (15-bit coefficients)
   produce values purecv misses by 1 to 6 levels. `cvt_color` to gray differs on 21,247 of
   the 2^24 RGB triples without `simd` and on 2,231,218 with `simd` (#191).
5. **Kernels and defaults that are something else:** `get_gaussian_kernel(n ≤ 9, σ ≤ 0)` is
   a sampled Gaussian where OpenCV uses fixed binomial tables, so every u8 `gaussian_blur`
   with `σ = 0` differs by up to 6; `median_blur` pads with reflect-101 where OpenCV pads
   with replicate (corner pixels differ by up to 222); `bilateral_filter` uses a square
   window and L2 colour distance where OpenCV uses a disc and L1; `HistCompMethods` numbers
   `Intersection`, `Bhattacharyya` and `ChiSqrAlt` differently from OpenCV; `Clahe` pads
   differently when only one dimension needs padding.
6. **Feature detectors with other semantics:** `canny` draws two-pixel-wide edges and never
   marks border pixels; the corner responses are OpenCV's times a constant (256 for Harris
   with block 3 and ksize 3, `255^4` more for u8 input); `pre_corner_detect`,
   `corner_sub_pix` and `hough_circles` follow other algorithms; `hough_lines_p` is not
   deterministic (OpenCV seeds its shuffle); `hough_lines` and `good_features_to_track`
   return OpenCV's set in another tie order.

What matches: the float paths of `gaussian_blur` (explicit σ), `blur`, `box_filter`,
`sobel`, `scharr`, `laplacian`; every u8 `erode`/`dilate`/`morphology_ex` case with
rectangular and cross kernels on all borders; u8 `pyr_down` and `build_pyramid`; `remap`
and `warp_perspective` with integer coordinates; `calc_hist` (uniform), `compare_hist`,
`equalize_hist` (no ties); `Clahe` when no padding question arises; the gray-to-colour
conversions.

Link bases used below: `H` = `https://github.com/opencv/opencv/blob/4.10.0/modules/imgproc/include/opencv2/imgproc.hpp`,
`S` = `https://github.com/opencv/opencv/blob/4.10.0/modules/imgproc/src` (written out in full in
every link).

## Notes

- **Counting.** The summary counts one row per table line (93 rows). Grouped rows (`erode`,
  `dilate`; the four `*_to_gray` helpers; each line of the missing table) count once.
- **D6.** `parallel` never changed a result. `simd` changed five rows (`cvt_color` to gray,
  `threshold`, `remap`, `warp_perspective`, `erode`/`dilate`/`morphology_ex`); the rows and [#234](https://github.com/webarkit/purecv/issues/234),
  [#235](https://github.com/webarkit/purecv/issues/235), [#237](https://github.com/webarkit/purecv/issues/237) and #191 carry the details. `wasm32` was not run.
- **Panics.** Three code paths panic on valid or plausible input ([#229](https://github.com/webarkit/purecv/issues/229), [#234](https://github.com/webarkit/purecv/issues/234), [#248](https://github.com/webarkit/purecv/issues/248)). The crate's
  rule is `Result` everywhere; these are the most urgent fixes the audit found.
- **IPP.** With IPP on, `cv2` returns different values for f32 `bilateralFilter` and `resize`,
  u8 `INTER_CUBIC` resize and `cornerHarris` with BORDER_REPLICATE. Not the reference.
- **Not measurable with `cv2`.** `BORDER_TRANSPARENT` in `remap` (uninitialised output
  buffer), non-uniform `calcHist` (no `uniform` argument). Both are `inspected` from source.
- **Inputs.** The scripts and the tests build every input from closed formulas
  (`((7y + 13x + 29c) · 37) mod 256`, `((x² + 3y) · 37) mod 256`, squares, lines, a ring), so
  no image file is committed.
